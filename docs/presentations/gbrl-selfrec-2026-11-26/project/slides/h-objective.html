Honest policy

Self-rec on honest code

Objective: distinguish between honest U_G (sender) and honeypots

Constraint: code has to pass tests / achieve the main task

Reward function components

P(YES | UG rewrite) = exp(log p(YES))exp(log p(YES)) + exp(log p(NO)) = σ(zYES − zNO)

  • log p: teacher-forced log-probs of YES / NO after “<answer>”; z: logits. The softmax normaliser cancels, so both forms are equal (YES, NO are single tokens)

Pass: does the rewrite pass the main task? Binary: 0 does not pass, 1 passes

R = P(YES | UG rewrite) · Pass

Short name in this deck: P(self | rewrite) = P(YES | U_G rewrite)

Why no component for honeypots?

  • Honeypots are static: they don’t change per rewrite
  • Honeypots are used only for the receiver U_M
